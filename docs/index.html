Core Capabilities

Everything You Need for Local Development

Built from the ground up to speak native RESP protocol and execute atomic Redis commands with WebAssembly.

🐂

Full BullMQ & Job Queue Compatibility

BullMQ relies heavily on atomic Lua scripts (`EVALSHA`, `EVAL`) to handle locks, token renewals, repeatable jobs, and delayed queues. `redis-local` embeds a real Lua 5.4 WebAssembly engine (`wasmoon`), allowing BullMQ to run flawlessly without crashes or missing commands.

⚡

Sub-Second Boot Time

Boots in under 500ms directly on Node.js. Run it on-demand in npm scripts or leave it running in a background terminal.

🌊

Redis Streams & Pub/Sub

Build real-time event-driven apps with full support for `XADD`, `XREAD`, `XRANGE`, `PUBLISH`, and `SUBSCRIBE`.

💾

Auto-Persistence (AOF/RDB Lite)

Save your dataset to disk seamlessly with the `--save` flag. Saves atomic JSON state snapshots on shutdown and auto-restores on boot.

🔌

Universal Client Support

Connects with any Redis client: `ioredis`, `@redis/client`, Python's `redis-py`, Go's `go-redis`, or the official `redis-cli`.

Easy Integration

Drop into Your Existing Stack in Seconds

No code changes required. Point your application to `localhost:6379` and you're ready to code. 

// 1. Start redis-local in your terminal: npx redis-local
import { Queue, Worker } from 'bullmq';

// 2. Connect directly to standard port 6379
const connection = { host: '127.0.0.1', port: 6379 };

const emailQueue = new Queue('emailQueue', { connection });

// 3. Add jobs with delays or retries
await emailQueue.add('welcome-email', {
  userId: 'usr_942',
  email: 'alex@example.com'
}, { delay: 2000 });

// 4. Process jobs
const worker = new Worker('emailQueue', async (job) => {
  console.log(`🚀 Processing job: ${job.id} for ${job.data.email}`);
}, { connection });
const Redis = require('ioredis');
const redis = new Redis({ port: 6379, host: '127.0.0.1' });

async function run() {
  await redis.set('session:user_12', JSON.stringify({ name: 'Sarah', role: 'admin' }), 'EX', 3600);
  const user = await redis.get('session:user_12');
  console.log('Cached User:', JSON.parse(user));

  // Pub/Sub
  redis.publish('notifications', 'Task completed successfully!');
}
run();

Frequently Asked Questions

Got Questions? We Have Answers.

Is redis-local meant for production? +
No. redis-local is specifically engineered for local development, rapid prototyping, and automated CI test runs. For production systems, you should use standard Redis Enterprise, AWS ElastiCache, or Redis Cloud.
Does it work with BullMQ out of the box? +
Yes! BullMQ requires atomic Lua scripts (like moving jobs between delayed, wait, and active sets). redis-local uses wasmoon (a WebAssembly-compiled Lua 5.4 engine) to provide atomic script execution with full redis.call() bindings.
Why not just use Docker Desktop? +
Docker Desktop requires WSL2 on Windows, consumes 2.5GB to 4.5GB of RAM just to keep the virtual machine alive, and is often blocked on corporate enterprise machines by IT policy. redis-local boots in under 500ms and uses only ~28MB of RAM.
How does persistence work? +
You can run npx redis-local --save or configure it in redis-local.conf. It snapshots your key-value pairs, hashes, sets, and streams into an atomic JSON dump file (redis-dump.json) upon shutdown or periodic intervals, restoring them when you boot back up.
Can I change the port or bind host? +
Yes! Just pass CLI arguments: npx redis-local --port 6380 --host 0.0.0.0 or configure your password with --requirepass secret123.
